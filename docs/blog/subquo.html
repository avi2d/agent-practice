Путь данных Subquo

Нажмите на элемент схемы, чтобы перейти к его описанию. С клавиатуры выберите элемент клавишей Tab и нажмите Enter.

вход аккаунта

Subquo читает только сохранённый вход явно названного аккаунта и держит его в памяти. Вход сохраняет и обновляет инструмент вендора, а Subquo его не записывает и не переключает.

refresh

Команда refresh запрашивает квоту каждого аккаунта из явного списка. Ожидание вендора остаётся здесь и не задерживает read. Ответ usage приходит от вендора в refresh.

usage вендора

Вендор сообщает остаток по окнам лимита и время сброса. Секрет и исходный ответ вендора не попадают в snapshot.

snapshot

Общий файл хранит наблюдения аккаунтов. Полученное значение содержит остаток по окнам, время сброса и время наблюдения. Команда refresh заменяет файл целиком, поэтому прерванная запись не оставляет половину файла.

read без сети

Команда read отдаёт последний полный snapshot без сети, ожидания блокировки и запроса пароля. При выводе текста read снова проверяет свежесть данных.

dashboard

Dashboard или планировщик сам выбирает аккаунт, пороги и порядок траты. Для выбора годятся только свежие наблюдения с известными значениями. Subquo не направляет задачи на аккаунты.

stale, unavailable

Устаревшее наблюдение stale сохраняет время наблюдения, поэтому его показывают с возрастом. Недоступное наблюдение unavailable содержит безопасный код причины, а не время наблюдения. Ни одно из этих состояний не подтверждает свободную квоту.

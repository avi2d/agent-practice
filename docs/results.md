# Соберите сводку результатов

Скрипт считает влитые запросы на изменение и проекты, в которые они вошли, за выбранный период.
Сводка называет открытые проекты, а для остальных показывает только общие числа.

## Запустите сбор

1. Установите Bun по версии из `.bun-version` и выполните `bun install` в корне репозитория.
1. Установите GitHub CLI и войдите через `gh auth login`.
   Проверьте, что выбранная учётная запись читает запросы во всех репозиториях, которые должны попасть в сводку.
1. Передайте первый и последний дни периода по UTC, затем укажите один или несколько логинов авторов.
   Подставьте свои логины вместо `example-author`:

   ```sh
   bun run results 2025-01-01 2025-12-31 example-author
   ```

1. Откройте файлы `data/results/<дата>.json` и `data/results/<дата>.md`.
   Имя файлов содержит дату сбора по UTC.
   Повторный запуск в тот же день заменяет оба файла.

## Проверьте, что вошло в сводку

Сравните даты и логины в JSON с теми, которые вы передали скрипту.
Скрипт включает обе даты, но не принимает текущий день по UTC.
Он ищет запросы по автору и дате слияния во всех доступных репозиториях, без списка организаций.
Скрипт считает каждый репозиторий с таким запросом одним проектом.

Сверьте общее число влитых запросов за весь период с [поиском GitHub](https://docs.github.com/en/search-github/searching-on-github/searching-issues-and-pull-requests).
Для каждого логина выполните поиск `is:pr is:merged author:<логин> merged:<первый день>..<последний день>` и сложите числа из поиска.
Сумма должна совпасть с полем `mergedPullRequests` в блоке `totals` JSON-файла и со строкой «Влитые запросы на изменение» в файле `.md`.

Если GitHub не вернул полную страницу поиска, скрипт завершится с ошибкой без новой сводки.
Если учётная запись не видит репозиторий в поиске, скрипт не может его учесть.
